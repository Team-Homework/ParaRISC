# ParaRisc 两人八周实施计划

> 日期暂按 2026-09-21 启动列示，实际启动日确定后整体平移。每周按“周初共同学习 → 周内分别开发 → 周末共同集成验收”推进，具体时段由两人协调。
>
> 本计划是分工和里程碑安排；仓库已有课程框架、Chisel 模板及部分开发中的文件。第 1 周列出的初始化任务按现有成果核对和补齐，不据此把功能模块视为已经完成。

配套文档：[项目目标](../project-requirements.md) · [A/B 分工与接口](project-ab-plan.md) · [执行清单](todo.md) · [双发射端口预算](port-budget-and-ipc.md) · [硬件设计指南](../guides/cpu-hardware-design-guide.md)

## 1. 八周结束时的共同目标

两人共同交付一个可复现的 Chisel RV32IM CPU 项目：

- 支持课程要求的 RV32IM 指令；不要求 CSR、ECALL、EBREAK、FENCE/FENCE.I、LB/LBU/LH/LHU，但必须支持 LW、SB、SH、SW 和八种 M 指令。
- 生成可供 Verilator 和 Yosys 使用的 Verilog，打通正确性、IPC、面积和时序评测。
- 先完成宽度 1 的正确性基线，再完成宽度 2 的前端、分派、发射、写回和提交主线。
- I-cache、D-cache 最终共享同一个下级内存；功能测试支持 3 周期，性能评测支持 20 周期延迟。
- 以面积不超过 40,000、IPC 不低于 1.0140、频率不低于 300 MHz 为冲刺目标；正式规则未确认前，不把该目标写成已达成事实。
- 提交参数敏感度分析、架构设计探索、复现说明和完整实验记录。

## 2. 共同学习与模块分工

| 角色 | 主责模块 | 主责验证与文档 | 必须理解并能调试的对方范围 |
| --- | --- | --- | --- |
| A：后端与正确性 | RMT/AMT、Free List、PRF/Busy、ROB、RS、双发射、ALU/Branch、AGU/LSQ、Store Buffer、恢复、公共类型 | 后端单测、独立 ISA 模型、提交对拍、核心参数实验、架构探索报告 | 能讲清 PC/预测/取指/译码、I/D-cache、统一内存仲裁和 MDU 握手；能从服务波形定位断供和迟到响应 |
| B：前端与系统服务（用户） | PC、预测器/训练队列、取指缓冲、双译码、I/D-cache、统一内存仲裁与模型、MDU、Top 和构建评测工具 | 前端/Cache/平台测试与参数实验、综合/时序/IPC 脚本、参数敏感度报告 | 能讲清重命名、物理寄存器生命周期、ROB/RS/LSQ 和恢复；能从提交轨迹定位资源账本、年龄和访存顺序问题 |

每周先一起学习本周双方要实现的模块，再按职责分别开发。两人都要理解这些模块在整机中的作用、基本原理、内部状态和相互接口，并能沿着一条指令说明模块如何配合。

1. 周初一起阅读相关材料、画数据通路、推演正常执行与停顿/恢复场景，覆盖 A、B 两边的模块。
2. 开发前共同明确接口和验收用例；接口至少说明字段、位宽、`valid/ready/fire`、背压、取消和复位规则。
3. 周内各自完成负责模块及测试，涉及公共接口或架构调整时及时同步。
4. 周末一起集成、运行回归，各自讲解关键实现和遇到的问题；另一人结合代码、波形或日志核对理解。
5. 将学习结论、接口约定、架构决策与实验结果记录在仓库，供后续开发和报告使用。

## 3. 每周固定节奏与完成定义

每周计划固定为四项：**周初共同学习、A 周内任务、B 周内任务、周末共同集成与验收**。学习内容随当周开发深入；第一周建立整体认识，后续逐周学习相关模块。具体开发方式由两人决定。

周初学习结束时，两人应能回答：本周模块各自做什么、保存哪些状态、如何交接数据，以及停顿或恢复时怎样协作。把这些结论落实为简要接口说明和测试场景，再分别开发。

每个模块只有同时具备以下内容才算完成：

- 可生成或可综合的实现；
- 单元测试，覆盖正常、背压、边界和取消/恢复场景；
- 接口与关键状态说明；
- 接入回归后没有破坏已经通过的用例。

周末共同验收后保存一次结果快照，包括源码版本、配置、通过/失败用例、周期数、已知问题和下周风险。性能实验还需保存 IPC、面积、关键路径或 WNS，以及主要 stall 计数。

## 4. 八周逐周计划

### 第 1 周（09-21～09-27）：工程启动、共同学习与 G0 接口冻结

**周初共同学习**

- 一起阅读项目目标、A/B 分工和端口预算，结合硬件设计指南建立整机认识，画出“取指 → 译码 → 重命名/分派 → 发射/执行 → 写回 → 按序提交”的数据流。
- 一起学习 Chisel 的组合/时序逻辑、寄存器、Bundle 和握手接口，以及生成 RTL、仿真、综合各自的作用；用一个带背压的简单模块推演状态变化。
- 确认课程侧尚未明确的事项：程序入口/退出、统一内存协议、3/20 周期精确定义、IPC 统计区间、综合面积口径和频率检查方法。未获得答案的部分做成可配置适配层并登记风险。
- 冻结 v1 公共契约：参数对象、`DecodedPacket`、redirect/预测训练、D/MDU 请求响应、Cache 下级内存请求响应、事务 ID、提交轨迹和最终排空协议。
- 建立代码审查、分支、测试命名和实验记录约定。

**A 周内任务**

- 建立 Backend 空壳、共享类型、译码包发生器、MockD 和 MockMDU，以及独立参考模型入口。
- 定义后端提交轨迹与架构对拍场景。
- 设计 RMT/AMT、Free List、PRF/Busy、ROB 的状态与资源账本，明确同拍释放/分配优先级。

**B 周内任务**

- 初始化 sbt/Chisel/chiseltest 工程、Verilog 生成入口和最小 CI/回归命令。
- 建立 Top、Frontend、预测器、I/D-cache/平台空壳、BackendSink 和服务事务驱动入口。
- 建立可配置的统一内存行为模型，以及 Verilator/Yosys 脚本骨架。

**周末共同集成与验收**

- 空壳工程能编译、运行至少一个 Chisel 测试并生成 Verilog。
- 前后端空壳能够连线；译码包背压、redirect 与旧包同拍取消至少有协议测试。
- 两人都能对照整机图解释各模块所有权、译码/重定向/预测训练/D/MDU 等跨域接口和宽度 1/2 的区别。

### 第 2 周（09-28～10-04）：宽度 1 基础数据通路与独立测试环境

**周初共同学习**

- 一起学习 PC、取指缓冲、译码、立即数和 ALU 的作用，沿一条整数指令梳理从取指到提交的过程。
- 一起学习 RMT/AMT、Free List、PRF/Busy 和 ROB：用连续读写同一寄存器的例子推演分配、写回、提交与回收。
- 一起学习八种 M 指令、乘除法基本算法及除零/溢出等边界，理解运算延迟与请求吞吐的区别。
- 共同明确 RV32IM 指令支持矩阵、译码字段和提交轨迹格式。参考 Chisel 速通的 ALU/寄存器堆章节、迁移文档的 PRF 章节及硬件指南的乘除法章节。

**A 周内任务**

- 完成宽度 1 的 RMT/AMT、Free List、PRF/Busy、ROB 分配/完成/提交基本路径。
- 完成整数 ALU、Branch/JAL/JALR 基本语义和单元测试。
- 让译码包发生器驱动 Backend，输出稳定的提交轨迹。

**B 周内任务**

- 完成 PC、顺序取指、取指缓冲和宽度 1 RV32IM 译码。
- 完成 MDU 的功能基线：迭代乘除或其他明确的首版结构，覆盖八种 M 指令和 ISA 边界条件。
- 用 BackendSink 验证前端背压、redirect、路径 ID 和迟到取指响应隔离。

**周末共同集成与验收**

- A 的宽度 1 后端可以让一组无访存整数指令按序提交，并由 A 的独立模型检查。
- B 的真实前端能输出正确译码包，MDU 随机/边界测试通过。
- 双方交换测试：B 运行并解释一次 ROB/PRF 测试，A 运行并解释一次取指/译码或 MDU 测试。

### 第 3 周（10-05～10-11）：调度闭环、真实前后端与 MDU 集成（G1/G2 前半）

**周初共同学习**

- 一起学习 RS 的就绪判断、唤醒、发射选择和写回仲裁，推演一组相关指令与一条长延迟乘除指令如何交错执行。
- 一起学习分支预测、实际分支判定、前端重定向与后端恢复的配合，明确哪些老指令保留、哪些年轻指令取消。
- 一起推演恢复时 IF/D/MDU 请求仍在途的情况，理解路径 ID、事务 ID、迟到响应与槽位复用。参考迁移文档的旁路/恢复章节和硬件指南的整机连接章节。

**A 周内任务**

- 完成宽度 1 RS、唤醒、发射、结果缓冲和写回仲裁。
- 接入真实 MDU，处理可变延迟、响应背压、事务 ID 和恢复后的迟到结果。
- 完成分支恢复基线，保证保留合法老指令并清除年轻错误路径状态。
- 建立独立 ISA 模型的整数/M 指令与提交对拍入口；模型直接解释原始指令，不复用 B 的硬件译码。

**B 周内任务**

- 完成真实 RV32IM 译码、立即数、SB/SH/SW 掩码控制字段及非法指令标记。
- 完成预测器与提交训练基线，测试方向/目标、元数据、重定向和旧取指响应隔离。
- 完善 MDU 结果保持、背压和吞吐测试；接入 Top。
- 将预测器接入取指端，并验证提交训练背压与重定向优先级。

**周末共同集成与验收**

- 宽度 1 的真实前端、后端和 MDU 能运行无 Cache 的整数/M 指令短程序并按提交轨迹对拍。
- 共同完成真实 Frontend ↔ Backend 连线，联测 redirect 优先级、包背压和错误路径取消；复核双方剩余工作量，必要时调整完整测试集或稳定叶模块的归属。
- 覆盖除零、`INT_MIN / -1`、乘法高半、错误预测时 MDU 在途等场景。
- 两人都能解释从译码包进入 Backend 到提交的逐拍过程，以及 MDU 响应为何不能仅凭 ROB 槽号识别身份。

### 第 4 周（10-12～10-18）：LSQ、统一内存直通与完整正确性基线（G2）

**周初共同学习**

- 一起学习 AGU、LSQ、Store Buffer 与统一内存仲裁器，画出一次 load 和一次 store 穿过双方模块的完整路径。
- 一起学习 LW/SB/SH/SW 的地址、字节掩码和数据排列，以及老 store 与年轻 load 的顺序关系。
- 一起区分 store 执行、架构提交、服务写确认与最终排空，推演 I/D 同时请求、背压、恢复和程序结束。参考硬件指南的统一内存章节，共同确定 3/20 周期模型与结束检查方法。

**A 周内任务**

- 完成单 AGU、LSQ、已提交 Store Buffer、保守访存顺序和 D 事务 ID 管理。
- 支持 LW、SB、SH、SW 的地址/掩码/数据处理；恢复时正确消费并丢弃无效迟到响应。
- 完成 A 域内 MockD 与后端 D 端口连线，验证访存事务 ID、背压和迟到响应。
- 扩充独立 RV32IM 参考模型和 store 架构效果检查。

**B 周内任务**

- 完成 D 直通、I/D 仲裁和统一内存适配器，支持随机请求/响应背压和 3/20 周期配置。
- 完成程序装载、复位、停止、排空和内存结果检查流程。
- 将 Verilator 功能回归整合为单命令执行。
- 建立 D-cache 事务驱动器和 MockMemory，验证掩码写、回填、写回与排空接口。

**周末共同集成与验收**

- 宽度 1 配置通过完整 RV32IM 单指令/随机短程序测试，并力争通过三项基础程序。
- 所有取指和数据请求接入同一个下级内存适配器；共同运行 3 周期内存的提交对拍，检查 store 架构效果和排空后的内存结果。
- I/D 同时请求、store 掩码、响应长期背压、分支恢复时 load 在途、最终排空测试通过。
- 若基础程序仍未全部通过，第 5 周前两天优先清零正确性问题，不带已知架构错误进入双宽开发。

### 第 5 周（10-19～10-25）：blocking I/D-cache 与真实长延迟路径（G3）

**周初共同学习**

- 一起学习 I/D-cache 的地址拆分、Tag/数据阵列、命中时序、miss 回填和脏行写回，分别画出两个 Cache 的状态机。
- 一起学习跨行取指、字节掩码写入和同步阵列端口限制，推演 I/D 同时 miss 时如何共享下级内存。
- 一起学习 Cache 与 LSQ/Store Buffer 的配合，明确 store 可见性、转发条件、恢复和最终排空。参考硬件指南的 Cache 与统一内存章节。

**A 周内任务**

- 完善 LSQ 与 Store Buffer 在 cache hit/miss、背压和脏写回期间的行为，先用 MockD 验证后端协议，再接 B 的 D-cache。
- 实现首版安全的 store-to-load 处理：未知老 store 地址时等待；可先支持单个老 store 完整覆盖时的 forwarding。
- 增加访存顺序、事务生命周期和排空断言/测试。

**B 周内任务**

- 完成 blocking I-cache：双指令所需行读取、跨行处理、miss 和回填。
- 完成 blocking write-back D-cache：SB/SH/SW 掩码更新、脏 victim 写回、回填与排空，并用 MockMemory 独立验证。
- 完成 I/D/写回统一仲裁及独立随机化测试，覆盖脏写回与背压。

**周末共同集成与验收**

- 真实 I/D-cache 下重复 hit、冷 miss、冲突 miss、跨行取指、脏替换和最终内存一致性测试通过。
- 一起运行 3/20 周期宽度 1 回归并检查 miss、回填和仲裁等待统计；A 讲解 LSQ 顺序与 store 可见性，B 讲解 I/D-cache 和统一仲裁。
- 宽度 1 整机通过三项基础程序，并开始跑 CPU Simulator 要求程序。
- 20 周期内存下得到第一份可信的宽度 1 IPC/停顿基线；这份数据用于定位，不作为最终成绩。

### 第 6 周（10-26～11-01）：宽度 2 端到端主线与联合回归（G4）

**周初共同学习**

- 一起学习整条双宽路径：双取指/译码、组内 RAW/WAW、连续前缀分派、双发射、双写回和双提交。
- 对照端口预算推演两条 ALU、两条访存、包内分支及多来源同时完成的场景，明确每个受限资源如何背压和保存请求。
- 一起学习流水乘法的启动间隔、独立迭代除法、预测训练队列，以及这些服务如何匹配后端吞吐。参考端口预算全文和硬件指南的多发射/流水乘法章节。

**A 周内任务**

- 完成双重命名的组内 RAW/WAW 前递、两项一致分配和连续前缀处理。
- 完成双发射选择、2 路 ALU/完成/PRF 写回、双提交和同拍资源账本。
- 覆盖 ROB/RS/Free List 回卷、非 2 次幂容量、恢复与双宽同拍边界。
- 完成双提交的预测训练输出，并验证训练背压不会丢失已提交的控制流结果。

**B 周内任务**

- 完成双取指/双译码包、包内控制流截断、跨行单槽退化和前端缓冲。
- 将乘法升级为目标 II=1 的流水实现或用实测说明保留方案；迭代除法保持独立运行。
- 完成双 PC 预测、最早跳转截断、预测采用通知、可同拍接两项训练的队列和历史恢复；完善 Top 级性能计数观测。

**周末共同集成与验收**

- 独立 ALU 诊断流稳定出现每拍 2 条分派、发射、完成和提交，诊断 IPC 目标先达到 1.5 以上。
- 共同接通整条宽度 2 路径，从独立整数流逐步增加依赖与资源冲突；复核工作量和关键路径，确定第 7 周的优化范围。
- 超额请求不会丢失或重复：双访存、写回冲突、MDU/Load 同拍完成、store 提交受限均有测试。
- 宽度 1/2 两种合法配置均通过回归；三项基础程序和 CPU Simulator 要求程序全部通过后才能进入最终性能收敛。

### 第 7 周（11-02～11-08）：测量驱动优化、参数扫描和报告初稿（G5 前半）

**周初共同学习**

- 一起学习 IPC 统计口径、面积报告和时序报告，理解为什么三项指标需要在同一配置、同一评测条件下比较。
- 一起阅读现有基线的计数器与关键路径，学习区分前端断供、访存等待、窗口不足和执行/写回冲突。
- 一起学习单参数对比、合法配置筛选和实验结果归因，确定双方实验矩阵及记录格式。参考设计指标文档和硬件指南的参数化/测量章节。

**A 周内任务**

- 扫描核心参数的精简集合，例如 `issueWidth={1,2}`、PRF `{48,64,96}`、ROB `{16,24/32,64}`、RS/Store Buffer 深度；先做单参数对比，再做少量组合实验。
- 根据计数器优化后端瓶颈，如窗口容量、发射公平性、写回保持、恢复或安全的 store forwarding。
- 完成架构设计探索报告初稿，记录采用/放弃方案及证据。

**B 周内任务**

- 扫描 I/D-cache 容量/相联度、预测器、前端缓冲和 MDU 配置；汇总 A 的核心原始实验数据。
- 跑 Yosys + ASAP7 面积流程和正式时序流程，定位面积大户与关键路径；维护一键复现脚本。
- 完成参数敏感度报告初稿和配置/实验数据表。

**周末共同集成与验收**

### 第 8 周（11-09～11-15）：冻结、全量验收、报告与交付（G5）

**周初共同学习与复盘**

- 一起复核关键设计取舍、参数实验结论与尚存瓶颈，确认两份报告的解释一致且有数据依据。
- 一起梳理从干净环境到生成 RTL、功能验证、性能/面积/时序评测的完整流程，明确最终交付清单；本周初冻结功能，后续集中修复和验收。

**A 周内任务**

- 负责最终后端定向测试、恢复/迟到结果和访存顺序压力测试，维护独立参考模型与提交对拍并修复本域缺陷。
- 定稿架构设计探索报告，补齐最终结构图、状态恢复、端口限制和已知不足。
- 向 B 做一次后端与架构对拍交接演练：从首个错误 commit 定位到 RMT/ROB/RS/LSQ 中的责任状态。

**B 周内任务**

- 负责最终前端、预测器、I/D-cache、Top/内存接口、Benchmark、面积、时序和复现脚本稳定性；配合 A 的提交对拍。
- 定稿参数敏感度报告与复现说明，生成最终 Verilog 和配置清单。
- 向 A 做一次前端与系统服务交接演练：从取指断供或错误响应定位到预测器、I/D-cache、仲裁或 MDU 状态。

**周末共同集成与最终验收**

- 正确性测试全绿，所有结果能由仓库内命令复现；若正式环境仍缺失，明确列出未验证项而不伪报完成。
- 共同执行全量指令、基础程序、CPU Simulator、20 周期 Benchmark、面积和时序检查，并从干净环境复现；确认调试观测不改变 CPU 行为或错误计入面积。
- 最终配置有完整的 IPC、面积和频率证据；未达到冲刺档时保留最稳妥正确配置，并用计数器解释主要差距。

## 6. 风险处理和范围优先级

当进度落后时，按以下优先级取舍：

1. 不牺牲正确性、统一内存约束、完整 RV32IM 和可复现评测。
2. 保住宽度 1 正确基线、blocking Cache 和宽度 2 端到端基本能力。
3. 根据测量选择少量高收益优化；高级预测、非阻塞 Cache、投机 load、复杂 store forwarding 等均为可选项。
4. 任一关键里程碑延期超过 2 个工作日，当天重新估算；优先砍掉尚未验证收益的可选优化，并为集成与报告保留最后一周。

三条硬性止损线：第 4 周末必须有宽度 1 整机基线，第 6 周末必须冻结宽度 2 的基本结构，第 8 周不做架构级重写。这样即使最高性能目标没有完全达到，仍能交付正确、可测量、可解释的完整项目。
