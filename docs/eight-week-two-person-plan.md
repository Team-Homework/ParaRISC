# ParaRisc 两人八周实施计划

> 计划起点：2026-09-21；若实际启动日变化，整体平移日期，周次和验收门槛不变。
>
> 本计划基于当前仓库状态制定：仓库现阶段只有设计文档，尚无 Scala/sbt 工程、RTL、测试和评测脚本。因此第 1 周包含工程初始化，不能把任何功能模块视为已经完成。

配套文档：[项目目标](../README.md) · [A/B 分工与接口](project-ab-plan.md) · [执行清单](todo.md) · [双发射端口预算](port-budget-and-ipc.md) · [硬件设计指南](cpu-hardware-design-guide.md)

## 1. 八周结束时的共同目标

两人共同交付一个可复现的 Chisel RV32IM CPU 项目：

- 支持课程要求的 RV32IM 指令；不要求 CSR、ECALL、EBREAK、FENCE/FENCE.I、LB/LBU/LH/LHU，但必须支持 LW、SB、SH、SW 和八种 M 指令。
- 生成可供 Verilator 和 Yosys 使用的 Verilog，打通正确性、IPC、面积和时序评测。
- 先完成宽度 1 的正确性基线，再完成宽度 2 的前端、分派、发射、写回和提交主线。
- I-cache、D-cache 最终共享同一个下级内存；功能测试支持 3 周期，性能评测支持 20 周期延迟。
- 以面积不超过 40,000、IPC 不低于 1.0140、频率不低于 300 MHz 为冲刺目标；正式规则未确认前，不把该目标写成已达成事实。
- 提交参数敏感度分析、架构设计探索、复现说明和完整实验记录。

## 2. 分工不等于知识隔离

| 角色 | 主责模块 | 主责验证与文档 | 必须理解并能调试的对方范围 |
| --- | --- | --- | --- |
| A：后端与正确性 | RMT/AMT、Free List、PRF/Busy、ROB、RS、双发射、ALU/Branch、AGU/LSQ、Store Buffer、恢复 | 独立参考模型、提交对拍、架构探索报告 | 能讲清 PC/预测/取指/译码、Cache miss/回填、统一内存仲裁和 MDU 握手；能从前端或服务波形定位断供、错误路径和迟到响应 |
| B：前端与系统服务 | PC/预测、取指缓冲、双译码、I/D-cache、统一内存仲裁与模型、MDU、Top、构建评测工具 | 服务测试、综合/时序/IPC 脚本、参数敏感度报告 | 能讲清重命名、物理寄存器生命周期、ROB/RS/LSQ、双提交和恢复；能从提交轨迹定位资源账本、年龄和恢复问题 |

共同学习不是让两人重复实现全部模块，而是通过以下固定动作保证任何一方都能理解整机：

1. 每周一进行 60 分钟架构讲解：模块负责人讲本周状态机、时序和风险，另一人复述数据流和失败场景。
2. 每个公共接口必须由两人共同评审；接口至少写明字段、位宽、`valid/ready/fire`、背压、取消和复位规则。
3. 每人每周至少审查对方一个实质性改动；重要模块合入前由非作者运行其测试并解释一条正常波形和一条异常波形。
4. 每周五共同运行一次整机回归，轮流担任集成值班：奇数周 A 主持、偶数周 B 主持。
5. 架构决策、参数、失败实验和评测口径写入仓库，避免知识只存在于口头讨论中。

## 3. 每周固定节奏与完成定义

建议每周按“周一设计对齐、周二至周四实现与单测、周五集成与复盘”推进。每个模块只有同时具备以下内容才算完成：

- 可生成或可综合的实现；
- 单元测试，覆盖正常、背压、边界和取消/恢复场景；
- 接口与关键状态说明；
- 接入回归后没有破坏已经通过的用例。

每周五保存一次结果快照，包括源码版本、配置、通过/失败用例、周期数、已知问题和下周风险。性能实验还需保存 IPC、面积、关键路径或 WNS，以及主要 stall 计数。

## 4. 八周逐周计划

### 第 1 周（09-21～09-27）：工程启动、共同学习与 G0 接口冻结

**共同工作**

- 通读项目目标、A/B 分工、端口预算和硬件设计指南；用一张整机图共同讲清“取指 → 译码 → 重命名/分派 → 发射/执行 → 写回 → 按序提交”的数据流。
- 确认课程侧尚未明确的事项：程序入口/退出、统一内存协议、3/20 周期精确定义、IPC 统计区间、综合面积口径和频率检查方法。未获得答案的部分做成可配置适配层并登记风险。
- 冻结 v1 公共契约：参数对象、`DecodedPacket`、redirect/train、D/MDU 请求响应、事务 ID、提交轨迹和最终排空协议。
- 建立代码审查、分支、测试命名和实验记录约定。

**A 本周任务**

- 建立 `common/` 类型初稿和 Backend 空壳。
- 建立译码包发生器、MockD、MockMDU 和参考模型入口。
- 设计 RMT/AMT、Free List、PRF/Busy、ROB 的状态与资源账本，明确同拍释放/分配优先级。

**B 本周任务**

- 初始化 sbt/Chisel/chiseltest 工程、Verilog 生成入口和最小 CI/回归命令。
- 建立 Top、Frontend、services 空壳、BackendSink 和事务驱动器。
- 建立可配置的统一内存行为模型，以及 Verilator/Yosys 脚本骨架。

**周末验收门槛**

- 空壳工程能编译、运行至少一个 Chisel 测试并生成 Verilog。
- 前后端空壳能够连线；译码包背压、redirect 与旧包同拍取消至少有协议测试。
- 两人都能对照整机图解释各模块所有权、四条跨域接口和宽度 1/2 的区别。

### 第 2 周（09-28～10-04）：宽度 1 基础数据通路与独立测试环境

**共同工作**

- 评审 RV32IM 指令支持矩阵、译码字段和提交轨迹格式。
- 用短指令序列共同推演 RAW、WAW、分支恢复、load/store 和 MDU 长延迟，确认状态更新顺序。
- 首次运行 Verilog 生成、Verilator 烟雾测试和 Yosys 空壳综合，尽早暴露工具问题。

**A 本周任务**

- 完成宽度 1 的 RMT/AMT、Free List、PRF/Busy、ROB 分配/完成/提交基本路径。
- 完成整数 ALU、Branch/JAL/JALR 基本语义和单元测试。
- 让译码包发生器驱动 Backend，输出稳定的提交轨迹。

**B 本周任务**

- 完成 PC、顺序取指、取指缓冲和宽度 1 RV32IM 译码。
- 完成 MDU 的功能基线：迭代乘除或其他明确的首版结构，覆盖八种 M 指令和 ISA 边界条件。
- 用 BackendSink 验证前端背压、redirect、路径 ID 和迟到取指响应隔离。

**周末验收门槛**

- A 的宽度 1 后端可以让一组无访存整数指令按序提交，并由独立模型检查。
- B 的真实前端能输出正确译码包，MDU 随机/边界测试通过。
- 双方交换测试：B 运行并解释一次 ROB/PRF 测试，A 运行并解释一次取指/译码或 MDU 测试。

### 第 3 周（10-05～10-11）：调度闭环、真实前后端与 MDU 集成（G1/G2 前半）

**共同工作**

- 完成第一次真实 Frontend ↔ Backend 连线，先跑无访存短程序。
- 联测 redirect 优先级、包背压、错误路径指令丢弃和提交轨迹顺序。
- 复核工作量：若一方剩余工作明显超过 55%，转移完整测试集、实验批次或稳定叶模块，不拆分紧耦合状态。

**A 本周任务**

- 完成宽度 1 RS、唤醒、发射、结果缓冲和写回仲裁。
- 接入真实 MDU，处理可变延迟、响应背压、事务 ID 和恢复后的迟到结果。
- 完成分支恢复基线，保证保留合法老指令并清除年轻错误路径状态。

**B 本周任务**

- 完成真实 RV32IM 译码、立即数、SB/SH/SW 掩码控制字段及非法指令标记。
- 完成简单分支预测/训练基线和前端重定向清空。
- 完善 MDU 结果保持、背压和吞吐测试；接入 Top。

**周末验收门槛**

- 宽度 1 的真实前端、后端和 MDU 能运行无 Cache 的整数/M 指令短程序并按提交轨迹对拍。
- 覆盖除零、`INT_MIN / -1`、乘法高半、错误预测时 MDU 在途等场景。
- 两人都能解释从译码包进入 Backend 到提交的逐拍过程，以及 MDU 响应为何不能仅凭 ROB 槽号识别身份。

### 第 4 周（10-12～10-18）：LSQ、统一内存直通与完整正确性基线（G2）

**共同工作**

- 将所有取指和数据请求接到同一个下级内存适配器，先采用单在途、保守顺序的功能基线。
- 建立按提交轨迹对拍的整机回归，区分 store 的架构提交和实际排空。
- 用 3 周期内存运行三项基础程序；失败时按提交轨迹定位到首个分歧。

**A 本周任务**

- 完成单 AGU、LSQ、已提交 Store Buffer、保守访存顺序和 D 事务 ID 管理。
- 支持 LW、SB、SH、SW 的地址/掩码/数据处理；恢复时正确消费并丢弃无效迟到响应。
- 扩充独立 RV32IM 参考模型和 store 架构效果检查。

**B 本周任务**

- 完成 D 直通服务、I/D 仲裁和统一内存适配器，支持随机请求/响应背压和 3/20 周期配置。
- 完成程序装载、复位、停止、排空和内存结果检查流程。
- 将 Verilator 功能回归整合为单命令执行。

**周末验收门槛**

- 宽度 1 配置通过完整 RV32IM 单指令/随机短程序测试，并力争通过三项基础程序。
- I/D 同时请求、store 掩码、响应长期背压、分支恢复时 load 在途、最终排空测试通过。
- 若基础程序仍未全部通过，第 5 周前两天优先清零正确性问题，不带已知架构错误进入双宽开发。

### 第 5 周（10-19～10-25）：blocking I/D-cache 与真实长延迟路径（G3）

**共同工作**

- 评审 Cache 地址拆分、命中时序、miss/回填、脏替换、统一内存仲裁和排空状态机。
- 在 3 周期与 20 周期两种条件下运行宽度 1 回归，记录 I/D miss、回填和仲裁等待计数。
- 两人交叉进行 Cache/LSQ 联合排错：A 解释 Cache 事务，B 解释 LSQ 年龄与 store 可见性。

**A 本周任务**

- 完善 LSQ 与 Store Buffer 在 cache hit/miss、背压和脏写回期间的行为。
- 实现首版安全的 store-to-load 处理：未知老 store 地址时等待；可先支持单个老 store 完整覆盖时的 forwarding。
- 增加访存顺序、事务生命周期和排空断言/测试。

**B 本周任务**

- 完成 blocking I-cache：双指令所需行读取、跨行处理、miss 和回填。
- 完成 blocking write-back D-cache：SB/SH/SW 掩码更新、脏 victim 写回、回填与排空。
- 完成 I/D/写回统一仲裁及独立随机化测试。

**周末验收门槛**

- 真实 I/D-cache 下重复 hit、冷 miss、冲突 miss、跨行取指、脏替换和最终内存一致性测试通过。
- 宽度 1 整机通过三项基础程序，并开始跑 CPU Simulator 要求程序。
- 20 周期内存下得到第一份可信的宽度 1 IPC/停顿基线；这份数据用于定位，不作为最终成绩。

### 第 6 周（10-26～11-01）：宽度 2 端到端主线与联合回归（G4）

**共同工作**

- 按端口预算接通 fetch/decode/rename/issue/writeback/commit 的宽度 2 路径。
- 用独立整数流证明稳态双处理能力，再逐步加入 RAW/WAW、双访存、分支、MDU 和 Cache 冲突。
- 第二次复核工作量与关键路径；冻结第 7 周可选优化清单，禁止无数据支撑的大规模重构。

**A 本周任务**

- 完成双重命名的组内 RAW/WAW 前递、两项一致分配和连续前缀处理。
- 完成双发射选择、2 路 ALU/完成/PRF 写回、双提交和同拍资源账本。
- 覆盖 ROB/RS/Free List 回卷、非 2 次幂容量、恢复与双宽同拍边界。

**B 本周任务**

- 完成双取指/双译码包、包内控制流截断、跨行单槽退化和前端缓冲。
- 将乘法升级为目标 II=1 的流水实现或用实测说明保留方案；迭代除法保持独立运行。
- 完善预测训练队列、双提交产生两项训练时的背压，以及 Top 级性能计数观测。

**周末验收门槛**

- 独立 ALU 诊断流稳定出现每拍 2 条分派、发射、完成和提交，诊断 IPC 目标先达到 1.5 以上。
- 超额请求不会丢失或重复：双访存、写回冲突、MDU/Load 同拍完成、store 提交受限均有测试。
- 宽度 1/2 两种合法配置均通过回归；三项基础程序和 CPU Simulator 要求程序全部通过后才能进入最终性能收敛。

### 第 7 周（11-02～11-08）：测量驱动优化、参数扫描和报告初稿（G5 前半）

**共同工作**

- 在正式或最接近正式的 20 周期条件下建立统一测量表，记录正确性、IPC、面积、频率/WNS 和 stall 计数。
- 只针对首要瓶颈选择优化：前端断供看 I-cache/预测，访存等待看 Cache/窗口/顺序，写回等待看仲裁，频率不足看关键组合路径。
- 每个优化单独提交并保留前后数据；收益不足或破坏面积/时序时可回退到已验证配置。

**A 本周任务**

- 扫描核心参数的精简集合，例如 `issueWidth={1,2}`、PRF `{48,64,96}`、ROB `{16,24/32,64}`、RS/Store Buffer 深度；先做单参数对比，再做少量组合实验。
- 根据计数器优化后端瓶颈，如窗口容量、发射公平性、写回保持、恢复或安全的 store forwarding。
- 完成架构设计探索报告初稿，记录采用/放弃方案及证据。

**B 本周任务**

- 扫描 I/D-cache 容量/相联度、前端缓冲、预测器和 MDU 配置。
- 跑 Yosys + ASAP7 面积流程和正式时序流程，定位面积大户与关键路径；维护一键复现脚本。
- 完成参数敏感度报告初稿和配置/实验数据表。

**周末验收门槛**

- 每个保留配置都通过正确性回归，实验记录能够由另一人复现。
- 确定一个“稳妥提交配置”和一个“性能冲刺配置”，并列出二者 IPC、面积、频率和风险。
- 两人互换报告审查：A 能解释 Cache/预测参数结果，B 能解释 PRF/ROB/发射宽度结果。

### 第 8 周（11-09～11-15）：冻结、全量验收、报告与交付（G5）

**共同工作**

- 周一冻结功能；之后只接受有回归覆盖的缺陷修复和低风险收敛，不再引入新架构。
- 对最终候选配置执行全量 RV32IM、基础程序、CPU Simulator、20 周期 Benchmark、面积和时序验收。
- 从干净环境按 README 复现依赖安装、Verilog 生成、测试、Benchmark、综合和报告数据。
- 清理临时调试逻辑，核对计数器不会改变被测 CPU 行为或被错误计入面积。

**A 本周任务**

- 负责最终提交对拍、恢复/迟到结果/排空压力测试和后端缺陷修复。
- 定稿架构设计探索报告，补齐最终结构图、状态恢复、端口限制和已知不足。
- 向 B 做一次后端交接演练：从首个错误 commit 定位到 RMT/ROB/RS/LSQ 中的责任状态。

**B 本周任务**

- 负责最终构建、Top/内存接口、Benchmark、面积、时序和复现脚本稳定性。
- 定稿参数敏感度报告与复现说明，生成最终 Verilog 和配置清单。
- 向 A 做一次前端/服务交接演练：从取指断供或错误响应定位到预测、Cache、仲裁或 MDU 状态。

**最终验收门槛**

- 正确性测试全绿，所有结果能由仓库内命令复现；若正式环境仍缺失，明确列出未验证项而不伪报完成。
- 最终配置有完整的 IPC、面积和频率证据；未达到冲刺档时保留最稳妥正确配置，并用计数器解释主要差距。
- CPU 源码、生成配置、测试、评测脚本、实验原始数据、两份报告和 README 使用说明齐全。
- 两人都能独立完成一次全流程运行，并能讲解整机架构、跨域协议、主要状态机和关键性能取舍。

## 6. 风险处理和范围优先级

当进度落后时，按以下优先级取舍：

1. 不牺牲正确性、统一内存约束、完整 RV32IM 和可复现评测。
2. 保住宽度 1 正确基线、blocking Cache 和宽度 2 端到端基本能力。
3. 根据测量选择少量高收益优化；高级预测、非阻塞 Cache、投机 load、复杂 store forwarding 等均为可选项。
4. 任一关键里程碑延期超过 2 个工作日，当天重新估算；优先砍掉尚未验证收益的可选优化，并为集成与报告保留最后一周。

三条硬性止损线：第 4 周末必须有宽度 1 整机基线，第 6 周末必须冻结宽度 2 的基本结构，第 8 周不做架构级重写。这样即使最高性能目标没有完全达到，仍能交付正确、可测量、可解释的完整项目。
